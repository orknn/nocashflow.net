## 1. Site nasıl build ediliyor?

Tek dosyalık Python static generator: **`build.py`** (2270 satır, harici bağımlılık yok — yalnız stdlib; sosyal kart üretimi için opsiyonel Pillow).

```
python3 build.py            # içerik partial'ı olan her sayfayı üretir
python3 build.py --clean    # önce /tr/ ağacını siler
```

Son çalıştırma: **66 çıktı** — 52 HTML sayfa + sitemap/robots/2 RSS + widget JSONP + 24 sosyal kart + günlük paylaşım görseli.

### Katmanlar

| Katman | Yer | Not |
|---|---|---|
| Ortak chrome (head, ticker, nav, masthead, footer, scripts) | `build.py` fonksiyonları | Tek kaynak |
| Sayfa gövdesi | `content/<lang>/<page>.html` | Dile göre ayrı partial |
| Sayfaya özel `<head>` | `content/head/<page>.html` | Opsiyonel, dil-ortak |
| Sayfaya özel kuyruk script | `content/foot/<page>.html` | Opsiyonel, dil-ortak |
| Makale gövdesi | `content/articles/<slug>/<lang>.html` | Metadata `build.py:ARTICLES` |
| FE deneme gövdesi | `content/fe/<key>/<lang>.html` | Metadata `build.py:FE_ESSAYS` |

**Kritik kural:** kökteki `.html` dosyaları **üretilmiş çıktıdır**. Doğrudan düzenlenirse ilk cron koşusunda ezilir. Düzenleme yeri: partial veya `build.py`.

### Sayfa kayıtları (registry'ler)

| Registry | `build.py` satırı | İçerik |
|---|---|---|
| `PAGES` | 398 | 14 statik sayfa (index, macro, calendar, embed, articles, dashboard, bulletin, about, glossary, finance-eng, disclaimer, privacy, legal, archive) |
| `ARTICLES` | 1493 | 9 makro makalesi |
| `FE_ESSAYS` | 1730 | 3 Finance Engineering denemesi |
| `INDICATORS` | ~1960 | `/now/` + `/tr/simdi/` canlı gösterge sayfaları |

**Yeni sayfa eklemek = registry'ye bir kayıt + `content/` altına iki partial.** Faz 3'ün Reference bölümü için altyapı uygun; şablon tabanlı yeni bir registry (ör. `REFERENCE`) aynı desende eklenebilir.

### Build determinizmi

HTML çıktısı **deterministik** — build'i çalıştırdım, commit'li halle byte-farkı yok. Tek istisna: `assets/cards/*.png` ve `share/daily.png` (Pillow çıktısı byte-stable değil, her koşuda "değişti" görünür). `bulletin-pdf.yml` bunu bilerek `git checkout -- assets/cards share` ile geri alıyor; `data.yml` almıyor.

## 2. Canlı piyasa verisi nereden geliyor?

**İki katman var ve ikisi de aynı DOM'u boyuyor.**

### Katman A — sunucu tarafı snapshot (build anı)

`scripts/fetch_data.py` · `fetch_markets.py` · `fetch_macro2.py` → `data/*.json`

| Dosya | Kaynak | İçerik |
|---|---|---|
| `data/market.json` | CoinGecko (BTC/ETH), Yahoo chart API (gold, brent, dxy, us10y, vix, spx, eurusd), alternative.me (F&G) | Ticker + KPI enstrümanları, her biri kendi `asof` damgasıyla |
| `data/calendar.json` | ForexFactory haftalık JSON (`nfs.faireconomy.media`) | Ekonomik takvim, US+EA, yüksek/orta etki |
| `data/macro.json` | FRED CSV (DGS2, DGS10, eğri, M2, DFEDTARU), Deribit (funding) | Getiri eğrisi, spread, Fed funds, ISM/Empire |
| `data/markets.json` | Yahoo / CoinGecko / DefiLlama | Dashboard "the tape" beslemesi |
| `data/macro2.json` | FRED + DefiLlama + Atlanta Fed + **Polymarket (cut odds)** | Macro "rejim" sayfası |
| `data/macro-notes.json` | **Elle yazılmış** | İnsan yorumları |

`build.py` bu JSON'ları modül seviyesinde okur (`MARKET`, `CALENDAR`, `MACRO`, `MARKETS`, `MACRO2`, `MACRO_NOTES`) ve HTML'e **gömer**.

### Katman B — istemci tarafı (tarayıcıda)

`app.js` (33 KB). Sırayla:

1. `/data/market.json`'ı same-origin çeker → `paintSnapshotAll()` ile anında boyar
2. CoinGecko'yu doğrudan çağırır (CORS uyumlu)
3. alternative.me F&G'yi doğrudan çağırır
4. Yahoo enstrümanlarını **CORS proxy zinciri** üzerinden çeker (corsproxy.io → allorigins → codetabs)
5. Coinbase Premium'u tarayıcıda hesaplar (Binance, GitHub Actions US IP'lerinden bloklu; tarayıcıdan erişilebiliyor)
6. `setInterval` ile periyodik tazeler

> **Not:** CORS-proxy + snapshot zinciri bilinçli bir mimari tercih — bu raporda bulgu olarak sayılmıyor, yalnız mevcut durum olarak tarif ediliyor.

## 3. Değerler build anında mı gömülüyor, runtime'da mı çekiliyor? ⭐

**İkisi de — ve Faz 1'in asıl konusu tam olarak burası.**

Sitede **iki farklı sınıf** sayı var:

### 3a. Bağlı (bindable) değerler — kendini düzeltebilir

`data-px="fg"` / `data-chg="fg"` gibi attribute'lu düğümler. Build anında `inject_market()` snapshot'tan doldurur, sonra `app.js` aynı düğümü canlı değerle **üzerine yazar**. Cron patlasa bile tarayıcı düzeltir.

Örnek (`content/en/index.html:22`):
```html
<div class="bs-kpi"><span class="k">Fear &amp; Greed</span>
  <span class="v" data-px="fg">—</span><span class="c neu" data-chg="fg">—</span></div>
```

### 3b. Bağsız (unbindable) değerler — **kalıcı olarak donuk** ⚠️

`build.py` bazı sayıları doğrudan **düz metin olarak** basıyor. Hiçbir `data-*` bağlaması yok, `app.js` bunlara dokunamıyor:

| Üretici | `build.py` | Çıktı | Nerede |
|---|---|---|---|
| `_mood_line()` | 83 | `Today the market is fearful — Fear &amp; Greed 29/100.` | **Her sayfanın footer'ı (52 sayfa)** |
| `_mood_pill()` | 96 | `<span class="mp-v">F&amp;G 29</span>` | Ana sayfa hero |
| `masthead()` | 903 | `Morning Edition · Friday, August 7, 2026 · Barcelona` | **Her sayfa** |
| `<body data-mood="fear">` | 1414 | mood'a bağlı CSS | Her sayfa |

Ayrıca `body` üstündeki ticker'da statik `<span class="dot"></span> Live` rozeti var — sayfa canlı olsun olmasın.

**Sonuç:** Bir makro denemesinin footer'ı, hiçbir canlı bağlantısı olmadan, kesin bir F&G rakamı beyan ediyor; masthead'i de o sayfayı bugünün "Morning Edition"ı ilan ediyor.

### Senin bildirdiğin tutarsızlık — doğrulama sonucu

Bildirdiğin tablo: index 29 · finance-engineering 11 · not-about-speed 22 · about 12.

**Bugün hem yerelde hem canlıda dördü de 29.** Canlı HTML'i curl ile çektim, dört sayfa da `Fear &amp; Greed 29/100` basıyor; `last-modified` dördünde de bugün 06:58 UTC. Service worker yok, Cloudflare proxy yok (DNS doğrudan GitHub Pages IP'lerine — `185.199.108–111.153`), `cache-control: max-age=600`.

Kritik gözlem: **gördüğün sayılar, aynı sayfalarda gördüğün donuk tarihlerle birebir eşleşiyor.**

| Sayfa | Gördüğün F&G | Gördüğün tarih | O tarihteki gerçek F&G |
|---|---|---|---|
| finance-engineering.html | 11 | 1 Temmuz | 1 Temmuz build'i |
| about.html | 12 | 29 Haziran | 29 Haziran build'i |
| not-about-speed.html | 22 | 9 Temmuz | 9 Temmuz build'i |
| index.html | 29 | bugün | bugün |

Yani her sayfa, **o sayfayı en son ziyaret ettiğin tarihteki build'i** gösteriyordu — büyük olasılıkla tarayıcı disk cache'i veya açık kalmış eski sekmeler. Üretim hattında bir kopukluk değil.

**Ama bulgunun kendisi geçerli ve düzeltilmeli:** sayı sayfaya çivilenmiş olduğu için, herhangi bir önbelleklenmiş kopya — ya da cron'un atladığı tek bir gün — siteyi "Live" rozeti altında kendinden emin bir yanlış sayı beyan eder duruma sokuyor. Kendini düzeltemeyen bir sayı, kredibilite açısından zaten kırıktır. Faz 1.1'in çözümü doğru çözüm.

### İkinci bulgu — sunucu tarafında sessiz eski-değere-düşme

`scripts/fetch_data.py:150` `build_market()`:

```python
def put(key, value, pct):
    if value is None:
        return  # keep last-good already in `inst`
```

Bir kaynak düşerse önceki değer **sessizce** korunuyor. Faz 1'in "sessizce eski değere düşme" kuralına aykırı. **İyi haber:** o enstrümanın `asof` damgası da eski kalıyor, yani bayatlık zaten veride tespit edilebilir durumda — yeni bir şema icat etmeye gerek yok, mevcut `asof`'u yüzeye çıkarmak yeterli.

`app.js` tarafında da aynı desen var: `localStorage` `ncf-market-cache` (`app.js:30-37`, `246`) — canlı çağrı düşerse önceki değeri sessizce boyuyor.

## 4. Deployment nasıl tetikleniyor?

GitHub Pages, `main` branch'inden doğrudan (`CNAME` + `.nojekyll`). Ayrı bir deploy workflow'u yok — **commit = deploy.**

İki GitHub Actions workflow'u var:

### `data.yml` — "Refresh data snapshots"
- **Cron:** `0 5 * * *` (her gün 05:00 UTC ≈ 07:00 CEST) + `workflow_dispatch`
- Adımlar: `fetch_data.py` → `fetch_markets.py` (continue-on-error) → `fetch_macro2.py` (continue-on-error) → **`python build.py`** → `git add -A` + commit + push
- Commit mesajı: `chore(data): refresh market + calendar snapshot [skip ci]`

### `bulletin-pdf.yml` — "Bulletin PDFs"
- **Tetik:** bülten botu `bulletins/{daily,weekly}/latest.{en,tr}.html` push'ladığında; ayrıca yedek cron (günlük 06:45 UTC, Pazar 20:30 UTC)
- HTML'in sha'sı değişmediyse PDF'i yeniden basmıyor (`.sha` sidecar) — geçmişte 238 MB blob şişmesine yol açmıştı
- Sonra `build.py` çalıştırıp arşivin bugünkü sayıyı listelemesini sağlıyor
- `git checkout -- assets/cards share` ile görsel churn'ünü geri alıyor

**Bülten içeriğini bu repo üretmiyor** — ayrı repo (`~/Sikik_Sikik_Fikirler/Crypto_Macro_Newsletter`) HTML'i buraya push'luyor.

### Sonuç: sitedeki tüm sayılar günde bir kez, 05:00 UTC'de yenileniyor
Her sayfa her gün yeniden üretiliyor. Sistem **tek bir cron koşusuna bağımlı**; o koşu düşerse 52 sayfa da bir gün önceki sayıyı basmaya devam eder ve bunu hiçbir yerde belli etmez.

## 5. `/tr/` ve `/` nasıl senkron tutuluyor?

Şablon seviyesinde, **runtime senkronizasyonu yok** — tek build iki dili birlikte üretiyor.

- `LANGS = ("en", "tr")`; EN kökte, TR `/tr/` altında
- Bir dilin sayfası **yalnızca o dilin partial'ı varsa** üretiliyor (`_exists(lang, page)`) — yarım göç canlı siteyi kırmıyor
- Yollar `PAGES[key]["paths"]` / `["out"]` sözlüklerinde dil başına ayrı tanımlı; TR slug'ları lokalize (`/tr/takvim.html`, `/tr/yazilar.html`, `/tr/hakkinda.html`, `/tr/sozluk.html`, `/tr/arsiv.html`, `/tr/simdi/`)
- Makale slug'ları da ayrı: `articles/core-inflation.html` ↔ `tr/yazilar/cekirdek.html`; FE için `FE_ESSAYS[key]["en_slug"]`
- **hreflang** `build.py:782-785` (statik sayfalar), `1632-1634` (makaleler), `1792-1794` (FE) — üç ayrı yerde, `en` + `tr` + `x-default`→EN
- Dil değiştirici her sayfada karşı dilin doğru yoluna işaret ediyor (`sw_href`)
- Sitemap her dil çiftini `xhtml:link` ile eşliyor

**Parite riski:** hreflang üç ayrı kod yolunda tekrarlanıyor. Faz 3'te yeni sayfa tipi (Reference) eklerken dördüncü bir kopya çıkacak — ortak yardımcıya çıkarmak mantıklı.

## 8. Faz planına ilişkin tespitler (uygulamadan önce kararın gerekli)

### 8.1 ⚠️ Faz 1.3'ün öncülü kısmen hatalı — bülten gerçekten günlük

Görevde "Site en az dört yerde 'published daily' diyor... son makale 14 Temmuz" deniyor ve tüm sıklık vaatlerinin **haftalığa** çevrilmesi isteniyor. Arşivi saydım:

| Ürün | Gerçek durum | Vaat doğru mu? |
|---|---|---|
| **Günlük bülten** | 56 sayı; **son 30 günde tek gün eksik yok** (2026-07-09 → 08-07 kesintisiz) | ✅ "every morning" **doğru** |
| **Haftalık bülten** | W24→W31, 8 hafta kesintisiz, her Pazar | ✅ "every Sunday" **doğru** |
| **Makaleler** | Son: `#09 cekirdek`, **2026-07-14** — 24 gün önce | ❌ düzensiz |

Yani "daily" vaatlerinin çoğu **bültene** ait ve doğrulanmış şekilde gerçek. Hepsini "haftalık"a çevirmek, gerçekten her sabah yayımlanan bir ürünü olduğundan az göstermek olur — kredibiliteyi düzeltmek yerine ters yönde bozar.

**Önerim:** vaatleri ürün bazında ayır.
- Bülten kadansı ("every morning", "07:45 CET", "Daily Pulse", bülten sayfasındaki kartlar) → **dokunma, doğrulanmış**
- "deep dive every Sunday" → haftalık bülten kastediliyorsa doğru; *makale* kastediliyorsa yanlış. Bu ifade `content/en/index.html:139`, `content/en/hakkinda.html:16`, `content/en/bulletin_page.html:112`'de geçiyor ve bağlamda bültenle aynı cümlede — **muhtemelen bülten**, ama senin niyetini bilmem gerekiyor.
- Ana sayfadaki `01–04 · Daily` seri etiketleri (`content/*/index.html:102-117`) → bunlar bültenin bölümlerini anlatıyor, makale değil; doğru.
- Footer sloganı "published daily" → `independent macro & markets` olarak değiştirmek yine de mantıklı (site bir bütün olarak günlük yayımlanmıyor).
- **Makale** tarafında sıklık vaadi olan yer varsa → düzelt.

Faz 1'e başlamadan bunu netleştirmen gerekiyor.

### 8.2 Faz 1.1 şeması — mevcut veri zaten daha zengin

Önerdiğin şema `metrics.fear_greed.value/label/as_of` + `source_map`. Mevcut `data/market.json` zaten enstrüman başına `px`/`chg`/`dir`/`asof` taşıyor ve `app.js` + `build.py` + `embed.js` + widget JSONP bu şekle bağlı. Şemayı baştan yazmak dört tüketiciyi birden kırar.

**Önerim:** mevcut şemayı koru, üzerine ekle — `source_map` ve enstrüman başına zaten var olan `asof`'u yüzeye çıkar. Aynı sonucu kırılma riski olmadan verir. Onay verirsen böyle uygularım; illa yeni şema istiyorsan tüketicileri de birlikte taşırım (daha büyük iş).

### 8.3 Faz 3.5 — matematik gösterimi

Stack'te **hiçbir matematik kütüphanesi yok** (KaTeX/MathJax/MathML aranmadı-bulunamadı). Formüller için üç seçenek var, 3.5'te sormamı istediğin karar bu:
1. Düz HTML + CSS (`<var>`, `<sup>`, `<sub>`) — sıfır bağımlılık, SEO/erişilebilirlik en iyi, karmaşık formülde sınırlı
2. KaTeX (~280 KB, self-host) — profesyonel görünüm, ağırlık ekler
3. MathML — modern tarayıcılarda native, Safari desteği iyi, sıfır JS

Kontrolörlük formülleri (PPV, standart maliyet, CCC) çoğunlukla dört işlem — **1. seçenek yeterli görünüyor**, ama karar senin.
